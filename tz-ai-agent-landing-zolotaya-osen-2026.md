# Техническое задание: лендинг РСХБ-Страхование на «Золотой осени — 2026»

## 1. Задача

Создай с нуля небольшую адаптивную одностраничную страницу для выставки «Золотая осень — 2026».

Страница будет открываться на смартфоне после перехода по QR-коду с раздаточной листовки. Она должна коротко объяснить посетителю, что находится на стенде РСХБ-Страхование и какие активности там проходят.

Это информационный лендинг, а не форма заявки и не продающая страница. Главный результат — посетитель понимает содержание стенда, даты выставки и место, где его найти.

Размещение планируется на домене или поддомене `rshbins.ru`. Точный URL можно добавить позже без изменения структуры страницы.

## 2. Целевая аудитория и тон

- Аудитория — все посетители выставки, а не только специалисты по страхованию.
- Текст должен быть понятным без специальных знаний и коротким.
- Тон — официальный, спокойный и информативный.
- Космическая тема выражается прежде всего через визуал, а не через сложные метафоры в тексте.

**Содержимое блока:**

- дата выставки;

На первом экране не должно быть кнопки, формы, QR-кода или другого отдельного CTA.

### Блок 3. Что будет на стенде

## 4. Визуальное направление

### Что использовать из PDF

- Из приложенного PDF использовать только изображение самого стенда как референс или визуальный материал.
- Подготовленный исходник рендера: `stand-render-page-02.png` — PNG, 4800×2700 px, рендер второй страницы PDF.
- Использовать этот файл как основной референс композиции, материалов, подсветки и фирменных деталей стенда. Если изображение ставится в отдельный блок страницы, кадрировать его по области рендера без лишних полей страницы.
- Не переносить в страницу остальные изображения и элементы PDF автоматически.

### Подготовленные визуальные материалы

Основные дополнительные материалы уже подготовлены и находятся в папке `generated-assets/` рядом с этим ТЗ. Использовать их как исходники, не генерировать заново без необходимости:

- `generated-assets/landing-background-light-future.png` — широкий светлый фон с футуристической архитектурой, орбитальными дугами и мягким аграрным мотивом;
- `generated-assets/orbital-lines-overlay.png` — прозрачный слой с орбитальными линиями, световыми траекториями и зелёными акцентами;
- `generated-assets/glass-architectural-accents.png` — прозрачный набор стеклянных, графитовых и световых декоративных элементов.

Разрешается аккуратно кадрировать, масштабировать, оптимизировать размер файлов и использовать материалы по отдельности в разных блоках. Не менять их цветовую логику и не добавлять поверх них случайные стоковые изображения.

Если для конкретного блока потребуется дополнительный визуальный акцент, создать его самостоятельно в той же стилистике: светлая футуристическая архитектура, стекло, графит, белая подсветка и ограниченные зелёные неоновые акценты.

Не использовать случайные стоковые изображения космоса. Визуальный язык должен выглядеть как продолжение конкретного стенда РСХБ-Страхование.

### Брендовые материалы с `rshbins.ru`

Официальные материалы взяты с сайта [rshbins.ru](https://rshbins.ru/) и уже подготовлены рядом с ТЗ:

- `generated-assets/site-favicon.svg` — основной favicon;
- `generated-assets/site-favicon-48x48.png` — PNG-фолбэк для браузеров и систем, которым нужен растровый favicon;
- `generated-assets/site-preview-logo-15.png` — официальный логотип РСХБ-Страхование с отметкой о 15-летии, исходник для превью ссылки.

На момент подготовки отдельного `og:image` на главной странице `rshbins.ru` не обнаружено. Если платформа требует стандартное превью 1200×630 px, собрать его на светлом фоне лендинга с использованием `site-preview-logo-15.png`; не подменять логотип случайной графикой.

### Стилистические признаки

- светлая футуристическая база, а не тёмный «космопорт»;
- графитовые поверхности;
- зелёный неон как фирменный акцент;
- белая подсветка;
- стеклянные и полупрозрачные поверхности;
- округлые космические формы;
- вертикальные линии и конструктивная геометрия;
- много воздуха и хорошая читаемость текста.

Не перегружать страницу свечением, градиентами и декоративными эффектами. Визуал должен поддерживать информацию, а не конкурировать с ней.

## 5. Анимация

Добавить ненавязчивую анимацию:

- мягкое свечение отдельных элементов;
- медленное движение фоновых орбитальных линий;
- плавное появление секций при прокрутке;
- лёгкое изменение прозрачности или положения декоративных элементов.

Не использовать резкие переходы, постоянное вращение крупных объектов, автовоспроизведение звука и тяжёлые 3D-эффекты.

Для пользователей с `prefers-reduced-motion: reduce` отключить или существенно сократить анимацию.

## 6. Адаптивность

Адаптивность должна быть максимально простой и предсказуемой. Не создавать отдельные мобильную и десктопную версии страницы.

- Использовать подход mobile-first: базовые стили и одноколоночная структура сначала проектируются для ширины 360–390 px.
- Сохранять один DOM и один порядок блоков на всех разрешениях.
- На планшете и десктопе расширять ту же структуру: при необходимости переводить отдельные секции в две колонки, но не строить сложные masonry-сетки.
- Использовать CSS Grid и Flexbox, `max-width` контейнера, относительные ширины и `gap` вместо ручного позиционирования.
- Не задавать фиксированные ширины и высоты для текстовых блоков. Не использовать `position: absolute` для раскладки контента; абсолютное позиционирование допустимо только для декоративных элементов.
- Сделать типографику, отступы и размеры крупных элементов плавными с помощью CSS-переменных и `clamp()`, где это действительно упрощает адаптацию.
- Изображения должны иметь `max-width: 100%`, сохранять пропорции и не вызывать горизонтальную прокрутку. Для медиа использовать `aspect-ratio` и `object-fit` только там, где это необходимо.
- Использовать минимум брейкпоинтов — предпочтительно один основной переход для планшета и один для широкого экрана. Не добавлять отдельные исправления под каждое устройство.
- Проверить страницу минимум на ширинах 360, 390, 768 и 1280 px.
- На мобильном экране текст, дата, время и адрес должны оставаться читаемыми без увеличения масштаба.
- Ссылки на соцсети и другие интерактивные элементы должны иметь удобную область нажатия не менее 44 px.

## 7. Технические требования для AI-агента

- Реализовать страницу с нуля как самостоятельный статический лендинг.
- Не добавлять backend, авторизацию, базу данных и формы отправки данных.
- Если среда не задаёт другой стек, использовать простой поддерживаемый вариант без лишней инфраструктуры: HTML, CSS и JavaScript либо эквивалентный лёгкий frontend-стек.
- Соблюдать описанный выше mobile-first подход и не усложнять адаптивность большим количеством брейкпоинтов.
- Не допускать горизонтальной прокрутки и наложения текста на мобильных экранах.
- Сжать изображения и не загружать тяжёлые ассеты без необходимости.
- Использовать семантическую разметку, видимый фокус клавиатуры и достаточный контраст текста.
- Добавить базовые `title` и `description` страницы.
- Подключить `generated-assets/site-favicon.svg` и PNG-фолбэк `generated-assets/site-favicon-48x48.png`.
- Подготовить Open Graph-превью с использованием `generated-assets/site-preview-logo-15.png`, если для публикации нужен отдельный файл превью.
- Не подключать системы аналитики и рекламные пиксели.
- Не вставлять QR-код на сам лендинг: он размещается только на печатной листовке.
- Все тексты, адресные поля, ссылки и визуальные ассеты хранить так, чтобы их можно было легко заменить.

## 8. Что проверить перед сдачей

1. На первом экране сразу понятны название компании, выставка и даты.
2. Все четыре активности стенда присутствуют.
3. Открытый урок вынесен в отдельный блок с датой и временем.
4. Адресный блок содержит только подтверждённые данные и пометки «уточняется».
5. Все шесть ссылок на социальные сети работают.
6. На странице нет QR-кода, формы, отдельного CTA и аналитических скриптов.
7. Из PDF использовано только изображение стенда; остальные материалы созданы отдельно в его стиле.
8. Страница хорошо читается на смартфоне и не теряет композицию на десктопе.
9. Анимация остаётся лёгкой и отключается при уменьшении движения в настройках пользователя.
10. В консоли браузера нет ошибок, битых ссылок и отсутствующих обязательных ассетов.
